# dur exits 0 when an input cannot be parsed

Our deploy script runs `dur` on the timeouts in our config and stops on a non-zero exit. A typo got through because `dur` exits 0 even when it cannot parse an input. From the script's log:

```
$ dur 1h30m 9Om 45s
5400000
error: cannot parse "9Om"
45000
done (ignore previous errors if any)
$ echo $?
0
```

Expected: exit code 1 when any input cannot be parsed, still printing the others, so a script can tell. The last line says to ignore previous errors, but a script cannot read it.
